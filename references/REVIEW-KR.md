# 검수와 완료 확인

[English](REVIEW.md) | [처음으로](../README-KR.md)

UI 검토나 의미 있는 변경을 확인할 때 사용한다. 모든 수정에 의무적으로 적용하는 절차가 아니다. 영향을 받은 화면과 예상 회귀를 확인하고 사용자가 요청한 출력 형식을 따른다.

## 근거 상태

검사 상태는 **PASS(통과)**, **FAIL(실패)**, **NOT_VERIFIED(미검증)**, **NOT_APPLICABLE(해당 없음)**로 표시한다. 계획한 검사는 통과가 아니라 미검증이다. 해당 없음에는 "이 양식에는 차트가 없음" 같은 이유가 필요하다. 이 상태를 검증되지 않은 미적 점수로 바꾸지 않는다.

근거와 해석을 구분한다.

| 근거 | 확인할 수 있는 것 | 이것만으로 확인할 수 없는 것 |
| --- | --- | --- |
| 소스·DOM 검사 | 선언된 라벨·핸들러·토큰·구조적 의미 | 실제 화면 배치·폰트 로딩·상호작용 상태의 가독성 |
| 렌더링 스크린샷 | 보이는 위계·잘림·간격·해당 상태 | 키보드 동작·정렬 정확성·보지 않은 상태 |
| 상호작용 시험 | 실제 수행한 행동과 상태 전환 | 수행하지 않은 경로·기기·보조 기술 전체 |
| 자동 접근성 검사 | 선택한 도구가 실제 확인하는 규칙 | 전체 접근성·제품 유용성·좋은 디자인 |
| 사람·작업 검토 | 시험한 사용자가 선택한 작업을 이해하는지 | 적절한 연구 없는 보편적 사용성·통계적 확실성 |

## 열 가지 규칙 점검

| 규칙 | 실제 결과물에서 확인할 것 |
| --- | --- |
| S01 | 사용자가 첫 질문·행동과 현재 범위를 알 수 있는가? |
| S02 | 핵심 읽기·작업 영역과 보조 정보를 구분할 수 있는가? |
| S03 | 글자·간격·모서리 역할이 일관되고 가장 작은 핵심 글자가 읽히는가? |
| S04 | 가장 큰 영역이 데이터를 왜곡하지 않으면서 공간을 쓸 가치가 있는가? |
| S05 | 행 식별·값 비교·긴 셀 확인·표시된 컨트롤 조작이 가능한가? |
| S06 | 수량·단위·기간·분류를 마우스를 올리지 않고 가까이에서 이해할 수 있는가? |
| S07 | 핵심값이 보이고 정확히 계산되며 유효한 기준으로만 비교되는가? |
| S08 | 반복되는 사실마다 추가 작업이나 맥락이 있는가? |
| S09 | 제공된 테마 사이에서도 팔레트와 상태 의미가 일관적인가? |
| S10 | 실제 서체가 언어·독자·위계·대체 폰트 환경에 적합한가? |

## 범위를 정확히 구분한 웹 접근성 점검

다음은 일부 점검 항목이며 WCAG 전체가 아니다. 출처는 [SOURCES](SOURCES-KR.md)에 있는 각 W3C 해설 문서이다.

| 검사 | 요건 또는 검토 경계 |
| --- | --- |
| 글자 대비: WCAG 1.4.3 | 일반 글자 최소 4.5:1, 큰 글자에 해당하면 최소 3:1. 큰 글자는 일반체 18pt 이상(24 CSS px) 또는 굵은 글자 14pt 이상(약 18.67 CSS px). 해당 기준의 예외를 적용한다. 미달 비율을 반올림해 통과시키지 않는다. |
| 비텍스트 대비: WCAG 1.4.11 | 컨트롤·상태·그래픽 객체를 식별하는 데 필요한 시각 정보는 해당 예외를 제외하고 일반적으로 인접 색과 3:1이 필요하다. 모든 장식용 구분선에 3:1을 요구하는 것은 아니다. |
| 글자 확대: WCAG 1.4.4 | 기준의 예외를 제외하고 200%까지 확대해도 내용·기능 손실이 없어야 한다. 200% 확인만으로 리플로 준수가 입증되지는 않는다. |
| 리플로: WCAG 1.4.10 | 일반적인 세로 스크롤 웹 콘텐츠는 폭 320 CSS px에 해당하는 조건에서 내용·기능 손실과 불필요한 양방향 스크롤 없이 사용 가능해야 한다. 표·캔버스처럼 본질적인 2차원 영역에는 예외가 있으나 주변 컨트롤·본문까지 일괄 예외가 되는 것은 아니다. |
| 포인터 대상: WCAG 2.5.8 | 최소 대상 크기는 24×24 CSS px이며 간격·동등한 컨트롤·인라인·사용자 에이전트·필수 표현의 예외가 있다. SANE의 더 큰 권장 조작 크기는 디자인 선호이지 이 최소값이 아니다. |

SANE은 의미에 맞는 컨트롤, 접근 가능한 이름, 키보드 조작, 보이는 포커스, 의미 있는 오류 문구, 색 이외의 상태 표현도 요구한다. 화면을 깔끔하게 보이게 하려고 포커스 표시를 제거하지 않는다. 불필요한 움직임을 피하고 사용자의 동작 줄이기 설정을 존중한다. 이 요구는 플랫폼의 전체 접근성 평가를 대체하지 않는다.

네이티브 앱은 해당 접근성 API, 글자 확대, 플랫폼 지침을 사용한다. 터미널 UI는 읽기 쉬운 순서와 일반 텍스트 대안을 제공하고 CSS 기반 준수를 주장하지 않는다.

## 변경에 비례하는 시험 상황

새로 만들거나 크게 바꾼 반응형 웹 화면은 대표 데스크톱·좁은 화면·해당되는 경우 320 CSS px 리플로 조건을 확인한다. 200% 글자 확대는 별도로 확인한다. 기기 픽셀과 CSS 픽셀을 혼동하지 않는다. 테마·언어를 제공하면 영향을 받은 조합을 확인한다.

컴포넌트가 실제로 만날 수 있는 정상 데이터·빈 데이터·로딩·오류·긴 내용 상태를 시험한다. 0과 결측은 따로 확인한다. 이상적인 샘플 데이터 스크린샷 한 장은 회귀시험이 아니다. 정적 페이지에 무관한 상태를 추가해 시험 범위를 만들어 내지 않는다.

작은 라벨·간격 수정이라면 해당 영역, 반응형 동작, 인접 회귀를 확인한다. 전체 조합 시험표가 자동으로 필요한 것은 아니다.

## 차단 결함과 개선 사항

**요청 범위의 차단 결함:** 핵심 글자를 읽거나 접근할 수 없음, 내용이 겹치거나 전체를 확인할 수 없음, 주요 컨트롤이 가짜이거나 고장남, 단위·라벨·시각 표현이 중대한 오해를 만듦, 샘플을 실제 데이터로 표시함, 지원하는 화면 크기·입력 방식에서 핵심 흐름이 사라짐, 필수 접근성 조건 실패.

**작업을 막지 않는 한 개선 사항:** 약간 불균형한 강조, 불필요한 카드 테두리, 읽을 수는 있지만 약한 서체 선택, 비핵심 반복, 경미한 토큰 불일치. 미적 규칙 위반 개수보다 사용자 영향을 우선한다.

알고 있는 범위 내 차단 결함이 있으면 준비 완료로 표시하지 않는다. 허용된 결함 수정은 불필요한 확인 반복 없이 진행한다. 자료·도구 한계로 해결하지 못하면 완료한 부분과 한계를 제공하고 통과를 암시하지 않는다.

## 간단한 검토 형식

검토를 요청받았을 때만 사용한다. 개수를 채우지 말고 중요한 발견부터 제한해서 제시한다.

```text
판정: READY / NEEDS_FIXES / PARTIALLY_VERIFIED
범위와 근거: [화면, 상태, 뷰포트, 실제 사용한 도구]
발견: [규칙 ID] [차단 또는 개선] [위치]
영향: [사용자가 읽거나 비교하거나 실행할 수 없는 것]
수정: [가장 작은 유효 변경]
미검증: [수행하지 못한 구체적 검사 또는 없음]
```

판정은 SANE 검토용 표기이지 인증이 아니다. 스크린샷만 검토했다면 눈에 띄는 시각적 차단 결함이 없어도 상호작용 검증의 한계를 밝힌다.
