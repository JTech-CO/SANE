# 디자인 규칙과 예외

[English](RULES.md) | [처음으로](../README-KR.md)

현재 결함과 관련된 규칙만 읽는다. 사용자가 제시한 열 가지 실패 유형을 바탕으로 독립적으로 작성한 실행 규칙이다. 아래 수치 기본값은 **SANE의 디자인 경험칙**이지 보편적인 표준이 아니다. 출처와 접근성 참고자료는 [SOURCES](SOURCES-KR.md)를 확인한다.

## S01 - 나열보다 작업이 먼저

**배제:** 시작할 이유가 없는 상태에서 가능한 위젯·필터·그래프·통계를 모두 추가한 화면.

**대체:** 사용자가 당장 해결할 질문이나 행동으로 첫 영역과 정보 순서를 정한다. 예외를 분류하는 작업이라면 과거 이력을 장식하는 그래프보다 예외 목록과 해당 범위를 먼저 보여준다. 필터는 영향을 주는 내용 가까이에 배치하고 활성 범위를 드러낸다. 세부 정보는 기존 탐색 경로나 범위 내 펼침 기능으로 확인할 수 있게 한다.

**확인:** 처음 보는 사람이 설명서를 열지 않고도 가장 먼저 무엇을 알거나 할 수 있는지 파악할 수 있는가? 첫인상 확인은 디자인 점검 방법이며 검증된 5초 성능 보장이 아니다.

**예외:** 전문가 모니터링에는 여러 신호의 동시 확인이 필요할 수 있고, 편집·탐색형 페이지에는 여러 진입점이 있을 수 있다. 하나의 거대한 KPI나 구매 버튼을 강요하지 말고 이들을 묶는 원칙을 정한다.

## S02 - 상자보다 위계가 먼저

**배제:** 모든 항목의 동일한 고대비 카드, 묶음 의미가 없는 중첩 패널, 서로 경쟁하는 여러 주요 행동.

**대체:** 읽기 순서, 크기, 위치, 묶음, 선택적인 대비를 사용한다. 반복되는 동급 항목은 같은 컴포넌트 스타일을 쓰되, 해당 섹션이 페이지 위계에서 어디에 놓이는지 분명해야 한다. 카드 경계가 가치를 더하지 않으면 행·제목·구분선을 우선한다. 대표 수치 없이 작업 캔버스 자체가 중심이 되어도 된다.

**확인:** 화면을 축소하거나 세부를 흐리게 보았을 때 의도한 첫 영역을 알아볼 수 있는가? 실제 원본 UI의 가독성도 확인한다. 이 방법은 접근성 검사를 대체하지 않는다.

**예외:** 같은 긴급도의 항목에 임의적인 중요도 차이를 주지 않는다. 비교 가능한 제품이나 경보의 그리드는 적절할 수 있다.

## S03 - 추측의 모음이 아닌 작은 척도

**배제:** 일회성 여백, 미세하게 다른 글자 크기 다수, 임의적인 모서리, 고정 높이로 잘린 문장, 화면에 넣기 위해 사용한 핵심 10px 라벨.

**대체:** 기존 토큰을 먼저 쓴다. 체계가 없으면 아래의 간결한 기본값으로 시작하고 명확한 역할이 있을 때만 추가한다. 크기 외에 굵기와 간격으로도 위계를 만든다. 긴 라벨은 줄바꿈하고 컴포넌트가 내용에 따라 늘어나게 한다.

**확인:** 영향을 받는 화면의 글자·간격·모서리 역할을 확인한다. CSS 변수 선언만 보지 말고 차트 글자와 표 라벨을 포함한 실제 계산값·렌더링을 비교한다. 가장 작은 의미 있는 글자를 일반적인 보기 크기에서 읽는다.

**예외:** 고밀도 전문가 도구에는 작은 보조 글자가 필요할 수 있으나 역할을 설명하고 검증한다. 압축 모드가 핵심 작업을 읽을 수 없게 만들어서는 안 된다. 네이티브 플랫폼에서는 웹 픽셀값을 그대로 쓰지 말고 접근 가능한 플랫폼 글자 척도를 쓴다.

## S04 - 공간은 작업에 기여해야 한다

**배제:** 시각적 효과만을 위한 큰 대표 그래프, 과도한 빈 카드 여백, 새로운 비교 없이 명확한 문장을 반복하는 차트.

**대체:** 질문에 맞는 가장 단순하고 정직한 표현을 고른다. 비교에는 막대, 시간 변화에는 선, 정확한 조회에는 표가 필요할 수 있다. 짧은 문장만으로 충분할 수도 있다. 데이터 범위를 바꾸기 전에 컨테이너 높이·위치·표현 방식을 조정한다. 차트 라벨과 점은 읽을 수 있어야 한다.

**확인:** 가장 큰 영역이 어떤 판단을 돕는가? 그 공간을 현재 작업에 더 유용하게 쓸 수 있는가? 일정 비율의 픽셀을 채우라고 요구하지 않는다. 희소한 분포와 의미 있는 빈 공간은 유효하다.

**예외:** 지도·분포·불확실성 구간에는 정당한 빈 영역이 생긴다. 이상치, 결측 구간, 의미 있는 축을 보존한다. 크기로 비교하는 막대의 수치축은 원칙적으로 0에서 시작하며, 0이 아닌 선·산점도 범위는 명확히 드러나야 한다. 점이나 관측치를 복제해 밀도를 꾸미지 않는다.

## S05 - 표도 인터페이스다

**배제:** 원시 필드 전체 동시 노출, 잘린 식별자, 마우스를 올려야만 확인되는 핵심 내용, 모호한 헤더, 실제 정렬 없는 정렬 아이콘.

**대체:** 작업에 맞는 기본 열과 정렬을 제공한다. 행의 정체를 알아볼 수 있는 위치에 식별 정보를 둔다. 비교하는 수치는 일관되게 정렬하며, 지원된다면 우측 정렬과 고정폭 숫자가 유용하다. 적절한 헤더나 셀에 단위를 표시한다. 긴 내용은 줄바꿈하거나 키보드·터치로 접근 가능한 상세 경로를 둔다. 보이는 열을 줄이더라도 필요한 전체 정보를 삭제하지 않는다.

**확인:** 특정 기록을 찾고, 두 값을 비교하고, 긴 셀 전체를 확인하고, 표시된 정렬·필터를 조작한다. 숫자·날짜를 문자열 사전순이 아닌 실제 자료형에 맞게 정렬하는지 확인한다. 작은 화면에서 핵심 글자를 줄이지 않고 국소 스크롤이나 대체 레이아웃을 사용할 수 있는지 확인한다.

**예외:** 원시 데이터 탐색기에는 많은 열이 필요할 수 있다. 폭이 사라진 것처럼 처리하지 말고 의도된 열 관리와 탐색을 제공한다. 작업상 필요하지 않은 검색·내보내기·페이지 이동을 이 규칙 때문에 추가하지 않는다.

## S06 - 의미는 표시 가까이에 둔다

**배제:** 설명 없는 0~9 축, 뜻풀이가 멀리 있는 약어, 단위 없는 숫자, 색만으로 구별하는 범례, 툴팁에 숨긴 핵심 정의.

**대체:** 수량명과 단위, 알아볼 수 있는 날짜, 명확한 분류, 비율의 분모를 가까이에 둔다. 해석에 영향을 주면 시간대·정규화·불확실성을 포함한다. 직접 라벨은 겹치지 않을 때 유용하다. 그렇지 않으면 간결하고 명확한 범례와 접근 가능한 대체 표현을 사용한다.

**확인:** 멀리 있는 부제목을 제외한 차트나 표만 보아도 값의 의미를 설명할 수 있는가? 긴 영문·한국어 라벨을 확인한다. 결측 기간과 0을 구분하고 없는 관측치를 조용히 보간하지 않는다.

**예외:** 관계가 명확하면 정렬된 작은 다중 차트가 라벨을 공유할 수 있다. 모든 점에 설명 전체를 반복하면 오히려 나빠진다. 그래도 핵심 해석에는 마우스를 올리는 행동이 필요 없어야 한다.

## S07 - 핵심 정보를 정직하게 드러낸다

**배제:** 보조 라벨에 숨은 핵심 지표, 근거 없는 추세 화살표, 만들어 낸 변화율, 기간·필터가 다른 비교.

**대체:** 사용자의 질문에 답하는 지표를 제공하고, 자료가 있다면 유효한 기준값·목표·비교 대상과 함께 보여준다. 무엇이 달라졌는지와 비교 기간을 밝힌다. 퍼센트포인트 차이와 상대 변화율을 구분한다. 정의와 필터를 일치시킨다. 상태 설명은 색에만 의존하지 않는다.

**확인:** 제공된 데이터로 파생값을 별도로 다시 계산한다. 단위·반올림·집계·개선 방향을 확인한다. 값이 낮다고 언제나 나쁜 것은 아니다. 과거 기록이 없다면 추세를 계산할 수 없는 것이지 0을 기준값으로 만들어도 되는 것이 아니다.

**예외:** 정직한 결과가 불확실성, 자료 부족, 서로 비교할 수 없는 여러 차원일 수 있다. 이를 하나의 점수로 강제하거나 상관관계를 인과적 발견으로 표현하지 않는다.

## S08 - 사실 하나에 대표 위치 하나

**배제:** 같은 범위와 작업을 설명하는 동일한 합계가 헤더·진행 바·우측 요약에 모두 표시되는 구성.

**대체:** 대표 위치 하나를 정한다. 다른 영역은 실제로 새로운 비교·설명·상세 정보를 제공하게 한다. 장식용 채움 요소를 다른 위젯으로 대체하지 말고 없앤다.

**확인:** 반복마다 추가로 지원하는 사용자 작업이나 맥락을 말할 수 있는가? 없다면 삭제하거나 통합한다.

**예외:** 표 합계, 국소 단위, 활성 필터 범위, 독립된 화면, 접근 가능한 텍스트 대안, 요약에서 상세로의 연속성은 자동으로 중복이 아니다. 차트를 다시 설명한다는 이유로 스크린리더 대체 내용을 지우지 않는다.

## S09 - 자동으로 입힌 옷이 아닌 일관된 분위기

**배제:** 기본적인 짙은 회색 배경과 형광색, 관련 없는 고채도 강조, 장식 발광, 떠다니는 그라디언트 도형, 제품 목적 없이 가독성을 약화하는 유리 패널.

**대체:** 배경·글자·보조 글자·테두리·행동·성공·주의·오류처럼 역할이 명명된 팔레트를 쓴다. 차트와 필터 사이에서 같은 분류의 색은 안정적으로 유지한다. 장식 효과에는 명시적인 브랜드나 상호작용 목적이 있어야 한다. UI 강조는 절제해서 시작하고 데이터가 요구하면 분류형·연속형 색상을 추가한다.

**확인:** 눈에 띄는 각 색을 역할로 설명할 수 있는가? 색 없이도 상태가 전달되는가? 기본 테마만이 아니라 제공하는 모든 테마에서 대비를 확인한다.

**예외:** 요청된 게임·음악 도구·레트로 UI·사이버 테마는 선명하거나 어두워도 된다. 대비·위계·일관성을 고치면서 정체성은 유지한다. 의미 있는 차트 팔레트에는 많은 색이 필요할 수 있다. 강조색 하나만 쓰는 미니멀리즘 때문에 분류를 없애지 않는다.

## S10 - 서체는 선택의 결과여야 한다

**배제:** 제품을 보지 않고 라이브러리 기본 서체를 채택하는 것, 기술적으로 보이려고 모든 본문을 고정폭 서체로 쓰는 것, 흔하다는 이유만으로 장식용 서체를 내려받는 것.

**대체:** 일관된 타이포그래피 방향을 정한다. 제목·본문 관계, 밀도, 굵기, 숫자, 문장부호, 언어 지원을 확인한다. 익숙한 산세리프나 시스템 스택도 의도된 올바른 선택이 될 수 있다. 한국어 화면은 라틴 서체가 한글도 지원한다고 가정하지 말고 실제 대체 서체와 혼합 문자의 균형을 본다. 사용 가능하고 허가된 폰트를 우선하며 이 패키지는 폰트를 제공하지 않는다.

**확인:** 대표 굵기에서 실제로 로딩된 폰트와 대체 폰트를 확인한다. 긴 이름, 한국어 문장, 라틴 식별자, 숫자, 폰트 로딩 실패를 시험한다. 개성 있는 서체는 핵심 읽기 경험을 느리게 하거나 깨뜨리지 않으면서 적합성을 높여야 한다.

**예외:** 플랫폼 기본 UI, 제한된 환경, 기존 브랜드 시스템은 시스템·일반 서체를 의도적으로 요구할 수 있다. 이를 보존하고 불필요한 폰트 교체 대신 비율·위계·레이아웃으로 정체성을 만든다.

## 조정 가능한 출발점

프로젝트에 적합한 체계가 없을 때만 쓰는 기본값이다. 필수 스타일시트도 아니고 정상적인 기존 토큰을 교체할 이유도 아니다.

| 영역 | SANE 출발점 | 경계 |
| --- | --- | --- |
| 본문 | `1rem`, 일반적인 브라우저 기본값에서 16 CSS px | 사용자 글자 설정을 존중하며 기준을 우회하려고 루트를 축소하지 않음 |
| 중요한 보조 글자 | `0.875rem`, 일반적으로 14 CSS px | 고밀도 비핵심 메타데이터는 검토 후 12px 가능. 핵심 라벨이나 넘침 회피에 쓰지 않음 |
| 글자 역할 | 약 4~6개. 예: 14·16·20·28·40px에 대응하는 크기 | 개수는 일관성 점검 도구이지 엄격한 상한이 아님 |
| 간격 | 4·8·12·16·24·32·48px에 대응하는 값 | 광학적 보정과 내용 수용을 허용하며 모든 치수가 간격 토큰은 아님 |
| 모서리 역할 | 0·4·8px 같은 작은 계열 | 알약·원형은 별도의 의미가 있을 수 있으며 둥근 모양을 금지하지 않음 |
