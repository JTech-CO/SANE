# 고정 템플릿 없는 수정 예시

[English](EXAMPLES.md) | [처음으로](../README-KR.md)

다음은 독립적으로 작성한 **설명용 예시**이며 실제 제품 지표·벤치마크·필수 레이아웃이 아니다. 실제 작업의 데이터와 브랜드를 보존한다.

## E01 - 위젯 벽이 아닌 고객지원 대시보드

**작업:** 조치가 필요한 지연 주문을 찾는다. 기존 다크 브랜드, 날짜 필터, 주문 상세 화면을 유지한다.

**잘못된 구성:** 같은 밝기의 KPI 카드 여섯 개, 전체 주문량을 보여주는 600px 대표 그래프, 세 영역의 같은 합계, 잘린 표, 동작하지 않는 내보내기 아이콘.

**수정:** 조치 가능한 지연 주문을 첫 작업 영역으로 둔다. 날짜 범위를 표시한다. 핵심 비율을 유효한 기준과 함께 한 번 배치하고, 해당 행에서 기존 상세 화면으로 바로 이어지게 한다. 분류 작업에 도움이 안 되는 과거 그래프는 줄이거나 옮긴다. 내보내기 기능을 새로 만들지 말고 가짜 아이콘을 제거한다. 기존 다크 팔레트에 더 명확한 의미별 강조를 적용한다.

**합성 비교 데이터:** 현재 기간 주문 100건 중 지연 14건, 같은 길이의 이전 기간 주문 100건 중 지연 10건. 정의와 필터 범위는 같다.

```text
지연 주문: 14 / 100건 (14%)
이전 기간: 10 / 100건 (10%)
지연율 차이: +4퍼센트포인트
지연율 상대 변화: +40%
```

작업에 유용한 비교만 보여주며 두 변화를 모두 표시할 의무는 없다. +4퍼센트포인트를 +4%로 표기하지 않는다. 지연율 증가는 부정적인 것이므로 자동으로 초록색 성공 화살표를 달지 않는다. 이는 S06·S07의 예시이지 모든 KPI에 적용할 권고가 아니다.

**규칙:** S01, S02, S04, S05, S07, S08, S09.

## E02 - 희소한 데이터는 레이아웃 버그가 아니다

**작업:** 제공된 관측치 네 개 `(2, 10)`, `(3, 12)`, `(4, 14)`, `(90, 70)`의 관계를 탐색한다. 단위와 라벨은 실제 요청에서 제공한다.

**잘못된 구성:** 마지막 관측치를 지우고, 알리지 않은 채 범위를 자르고, 나머지 점을 복제해 그래프를 채운다.

**수정:** 네 점을 모두 보존한다. 적절한 차트 크기와 명확한 축 라벨을 쓰고, 핵심 질문이 아니라면 상세 영역으로 옮긴다. 변환 축이 타당하다면 이를 명시하고 해석 가능성을 유지한다. 정확한 조회가 필요한 제품에는 간결한 데이터 대안을 제공한다. 빈 공간이 많은 산점도가 올바른 표현일 수 있다.

**추론하지 않을 것:** 네 점으로 인과관계·신뢰할 만한 추세·적절한 차트 밀도 목표가 입증되었다는 주장.

**규칙:** S04, S06, S07.

## E03 - 한국어 편집기는 흔한 서체를 유지해도 된다

**작업:** 영문·한국어 데스크톱·모바일 글쓰기 편집기의 잘림과 답답한 글자 배치를 고친다. 기존 시스템 산세리프와 다크 테마는 의도된 선택이다.

**잘못된 구성:** 생소한 라틴 디스플레이 서체로 바꾸고, 지표 사이드바를 추가하고, 한 줄에 넣으려고 한국어 도구 라벨을 10px로 줄인다.

**수정:** 편집 캔버스를 주 영역으로 유지한다. 의도된 서체를 유지하고 한글 대체 서체를 확인한다. 소수의 글자·간격 척도를 사용하며 라벨이 줄바꿈하거나 재배치되게 하고 정상 동작하는 명령은 보존한다. `배포 상태 / Deployment status`, `₩1,234,567`, 긴 영문 식별자 같은 혼합 문장을 확인한다. 외부 폰트 요청 실패는 대체 서체 시험이지 빈 글자를 보여도 된다는 뜻이 아니다.

**규칙:** S01, S02, S03, S05, S10. 표가 없다면 표 전용 검사는 해당 없음이다.

## E04 - 설정 페이지에는 대표 그래프가 필요 없다

**작업:** 알림 설정을 변경하고 저장한다.

**잘못된 구성:** 환영 배너, 사용량 KPI 네 개, 무관한 활동 차트, 같은 강도의 주요 행동 세 개, 상태가 바뀌지 않는 장식 토글.

**수정:** 의미별로 설정을 묶고 실제 값을 유지하며 각 라벨을 명확히 한다. 정상 동작하는 저장 행동과 범위 내 피드백을 제공한다. 분석 기능이나 새로운 설정 분류를 추가하지 않는다. 간단한 양식만으로도 완전하고 개성 있는 결과가 될 수 있다.

**규칙:** S01, S02, S03, S06, S08, S10. 차트·통계 비교 규칙은 해당 없음일 수 있다.

## E05 - 의도한 네온도 약한 위계의 변명이 되지는 않는다

**작업:** 검은 배경과 네온 브랜드가 명시된 음악 공연 앱을 고친다.

**잘못된 구성:** AI풍을 없앤다는 이유로 요청 테마를 지우고 베이지색 관리 페이지를 만든다.

**수정:** 브랜드를 유지하고 네온 강조색의 역할을 고정한다. 강한 강조는 실시간 작업 상태에 우선 배정하며 대비와 라벨 간격을 고친다. 준비·재생·정지를 색뿐 아니라 글자나 형태로도 구분한다. 실제 공연 시야에서 필수 컨트롤이 분명해야 한다.

**규칙:** S02, S03, S09, S10.

## E06 - 터미널 출력도 인터페이스다

**작업:** 웹 UI가 아닌 기존 CLI 상태 보고를 개선한다.

**잘못된 구성:** 전용 웹폰트를 지정하고, 모든 행을 둥근 카드로 만들고, 빨강·초록 ANSI 색상에만 의존한다.

**수정:** 요약과 조치 가능한 실패를 먼저 묶고 열·단위에 라벨을 붙인다. 긴 식별자는 전체 확인이 가능하게 한다. 색을 끈 일반 텍스트에서도 이해할 수 있어야 한다. 터미널이 지원하는 동작을 사용하고 기계용 출력 모드는 유지한다. 사용자의 터미널 폰트를 제어한다고 주장하지 않는다.

**규칙:** S01, S02, S05, S06, S07, S08, S09. 웹폰트와 CSS 치수는 해당 없음이다.

## 범위를 제한한 수정 프롬프트

```text
첨부한 대시보드의 보이는 글자와 라벨에만 SANE을 적용한다.
S03·S06 문제를 고친다. 현재 테마, 데이터, 컴포넌트 동작,
무관한 레이아웃을 유지한다. 기능이나 폰트 라이브러리를 추가하지 않는다.
관련된 렌더링 검사 중 실행하지 못한 항목은 밝힌다.
```

검토 전용 요청이라면 발견 사항을 요청하고 수정하지 말라고 명시한다. 신규 제작에서는 실제 사용자와 작업을 제공한다. 예시 레이아웃을 제품 요구사항인 것처럼 붙이지 않는다.
