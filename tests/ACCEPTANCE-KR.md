# 행동 검증 사례

[English](ACCEPTANCE.md) | [처음으로](../README-KR.md)

**상태: NOT_RUN(미실행).** 실행할 수 있는 평가 과제이며 결과가 아니다. 이번 릴리스에서는 외부 모델·네이티브 스킬 로더 전체에서 사례를 실행하지 않았다. 패키지 자체의 검사는 [RELEASE-CHECK](RELEASE-CHECK-KR.md)에 별도로 있다.

선택 언어의 LITE 또는 SKILL을 한 번 적용하고 사례의 입력과 필요한 시험 자료를 제공한다. 모델이 지켰다고 선언하는지가 아니라 실제 결과물을 본다. 기존 코드 사례는 운영 저장소가 아닌 폐기 가능한 시험 저장소를 사용한다.

## 의미 있는 비교 방법

작업 입력·시험 데이터·호스트·모델 버전·사용 가능한 도구·뷰포트·관련 생성 설정을 같게 둔다. 기본 요청과 SANE을 포함한 요청을 비교한다. 진입 파일이 실제 로딩되었는지 기록한다. 가능하면 반복하고 변동성도 보고한다. 좋은 사례 하나로 보편적인 개선이 입증되지는 않는다.

해당되는 사례마다 적용 경로, 규칙 ID, 실제 근거, PASS·FAIL·NOT_VERIFIED·NOT_APPLICABLE, 범위 내 차단 결함을 기록한다. 렌더링 도구가 없는 호스트는 지시문 전달 검사를 통과하더라도 시각 품질은 미검증일 수 있다. 해당 없는 사례는 이유를 밝히고 성공 횟수로 세지 않는다.

수용 기준은 데이터·범위·브랜드·동작을 보존하면서 관찰 가능한 작업·가독성 개선이 있는가이다. 답변에서 반복한 금지 규칙 수나 자기검토 길이가 아니다.

## 간단한 실행 기록

```text
호스트 / 모델 / 버전:
계약: LITE 또는 SKILL; EN 또는 KR; 패키지 버전:
적용 경로와 로딩 근거:
사례 / 원본 시험 자료 / 뷰포트 또는 터미널 폭:
관찰 결과와 근거:
상태: PASS / FAIL / NOT_VERIFIED / NOT_APPLICABLE
차단 결함(있는 경우):
회귀·범위 위반(있는 경우):
```

해당 실행 기록이 생기기 전에는 README에 설치 성공이나 여러 모델의 성능을 검증했다는 주장을 추가하지 않는다.
